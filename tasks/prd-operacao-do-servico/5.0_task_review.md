## Recomendações (não bloqueiam)

1. `app/jobs/webhooks.py:181-191` — `put_destination` decide criação por `account.webhook_url is None`. Uma conta com material corrente mas sem URL (estado alcançável por fluxos legados da CLI) cai em `_configure`, que levanta `WebhookConfigurationError` e vira `500` em `app/main.py` (handler genérico). Considere tratar esse estado de forma explícita (ex.: troca de endereço preservando o material) ou ao menos coberto por teste.
2. `app/jobs/webhooks.py:184` — a resolução DNS da ADR-003 roda de novo dentro da transação, com a linha da conta travada por `FOR UPDATE`. É correto (evita TOCTOU de configuração), mas um DNS lento segura o lock; a validação já feita antes da transação (sem lock) poderia bastar ou ter timeout curto documentado.
3. `api-contract.yaml` — a resposta `404` de `getWebhookDestination` referencia apenas `NotFound` (`code: NOT_FOUND`), enquanto a task e a implementação usam `DESTINATION_NOT_FOUND` para conta sem destino. Vale acrescentar o exemplo/código ao contrato para não divergir de consumidores gerados.
4. `tests/test_v05_operator_destination.py:281` — "conta sem destino continua com a API Key aceita na API pública" é provado via `credential_store.authenticate(...)`, não por uma chamada HTTP à API pública. Uma requisição autenticada real deixaria o critério ponta a ponta.
