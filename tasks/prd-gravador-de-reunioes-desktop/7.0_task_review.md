## Recomendações (não bloqueantes)

1. **Estado após uma substituição recusada** (`src/Core/Access/ApiAccessService.cs:54-57`): quando uma candidata é recusada ou não verificável e já existe uma chave salva, o estado passa a `Rejected`/`Unverifiable` com o `MaskedKey` da chave antiga. Com isso, `CanSend` fica `false` até o próximo `CheckSavedAsync`. `RequestSendAsync` revalida antes do envio, então a jornada não quebra. Ainda assim, a tela da 8.0 deve deixar claro que o resultado é da candidata e não da chave salva.
2. **"Conta desativada" sem um modelo de domínio**: a API não tem flag nem operação para desativar uma conta. O cenário revoga todas as credenciais da conta pelo ciclo real (isso está documentado no README e na fixture). É aceitável, mas, se a API ganhar a desativação de conta, o teste deve passar a usá-la.
3. **Posse do handler** (`src/Core/Access/ApiAccessProbe.cs:66`): `Dispose` descarta também um `HttpMessageHandler` injetado pelo chamador. Hoje isso é inofensivo, mas convém só descartar o handler quando o próprio probe o criou.
4. **Higiene da árvore para o checkpoint**: há mudanças fora do escopo da task (`.agents/skills/*`, `routing.default.json`, `README.md` da raiz, todas ligadas à remoção do `rtk`) e o diretório `local_meeting_transcriber.egg-info/`, que não está no `.gitignore`. O integrador não deve incluí-los no checkpoint da 7.0, e o `egg-info` deveria entrar no `.gitignore`.
