## Bloqueantes

### B-01: `TranscriptViewModel.Open` deixa escapar `InvalidDataException` e derruba o chamador

- **Onde:** `clients/windows-recorder/src/Core/Transcripts/LocalTranscriptStore.cs:41-48` lança `InvalidDataException`. O filtro em `clients/windows-recorder/src/Presentation/Transcripts/TranscriptViewModel.cs:34-35` captura `IOException, UnauthorizedAccessException, JsonException, InvalidOperationException, KeyNotFoundException, FormatException`. `System.IO.InvalidDataException` deriva de `SystemException`, não de `IOException`, então fica de fora.
- **Reprodução** (projeto à parte no scratchpad, que referencia Core/Presentation, sem tocar na árvore). Gravação `transcribed` com `result-v1.json` igual a:
  - `{"segments":[]}` (sem `schemaVersion`) → `UNHANDLED System.IO.InvalidDataException`
  - `{"schemaVersion":"2"}` (versão não numérica) → `UNHANDLED System.IO.InvalidDataException`
  - `{"schemaVersion":1,"segments":[{"startMs":-5,"text":"a"}]}` → `UNHANDLED System.IO.InvalidDataException`
- **Por que bloqueia:** a ViewModel declara (código e README V-08) que uma falha de leitura local vira a mensagem "Não foi possível ler a transcrição local…" e limpa o estado. Com estas entradas, a exceção sai de `Open`. Na tela da 14.0, isso é exceção não tratada num comando de UI. O caso é alcançável com dados que o próprio app grava: `JobTracker.StoreResult` (`src/Core/Tracking/JobTracker.cs:161`) persiste `result-v1.json` **antes** de validar `schemaVersion`/`startMs` (linhas 164-172). Além disso, um arquivo local corrompido ou editado pelo usuário já basta. Nesses casos o app quebra em vez de manter a gravação visível com uma mensagem.
- **Correção esperada:** tratar `InvalidDataException` na ViewModel (ou lançar um tipo já tratado no store), com teste V08 para JSON sem `schemaVersion`, com versão não numérica e com `startMs` negativo, verificando a mensagem de erro e o estado limpo. Não enfraquecer os testes existentes.

## Recomendações (não bloqueiam)

1. **R-01:** decidir explicitamente se `schemaVersion` presente mas não inteira (por exemplo `"2"` ou `1.5`) deve cair em "atualize o app" (RF/techspec: versão desconhecida preserva e pede atualização) ou em "não foi possível ler". Hoje cai no erro do B-01.
2. **R-02:** `CopyText(includeTimestamps: false)` inclui uma linha vazia para cada trecho só com espaços quando há outros trechos com fala. Avaliar se esses trechos devem ser omitidos na cópia sem tempos.
3. **R-03:** `Message` de `Unavailable` após um `Open` que falhou repete "Abra uma transcrição…", o que esconde que a última leitura falhou. Isso é cosmético e pode ficar para a 14.0.
