## Entrega e evidência

Solução `Whisper.Recorder.slnx` com cinco projetos: Core e Presentation em
`net10.0`, Host WPF em `net10.0-windows`, Core.Tests e Host.Tests. O host referencia
a apresentação, que referencia o núcleo. A apresentação não referencia WPF e o
cliente não importa o serviço Python. A apresentação e os testes Windows são
bases para as próximas fatias; Host.Tests ainda não contém testes.

As seis portas estão no núcleo: captura (fontes independentes, dispositivos,
blocos PCM com timestamp/formato, nível e disponibilidade), cofre, notificador
(inclusive indicador de gravação), reprodutor com posição, relógio e agendador.
Todas têm dublês reutilizáveis. Relógio e agendador também têm implementações do
sistema. O diagnóstico só aceita eventos enumerados válidos e escreve timestamp
e evento, sem mensagens livres, exceções, caminhos, HTTP, conteúdo ou segredo.
O host registra início/saída em `%LOCALAPPDATA%\Whisper\Recorder\diagnostics.log`.

O cliente HTTP e os modelos são gerados por Kiota 1.36.1, fixado no manifesto
local; o runtime Microsoft.Kiota.Bundle também está fixado. O comando reproduzível
é `.venv/bin/python clients/windows-recorder/scripts/generate_api.py`, executado
da raiz. O script lê o contrato aprovado e prepara uma cópia intermediária com
inteiros sem formato como int64: o padrão int32 do gerador não suporta o limite
de 5 GiB de sizeBytes. Não houve alteração de contrato. O smoke verifica a
serialização dos 5368709120 bytes e do tipo audio/wav, sem enviar requisições.
A segunda geração manteve hashes SHA-256 idênticos dos 22 arquivos produzidos
(21 fontes/lock versionáveis e o log transitório ignorado do gerador).

O runner Microsoft.Testing.Platform está selecionado no global.json da raiz;
os projetos usam xUnit/MTP v2 e mínimo padrão de 1 teste. Há exatamente um smoke
no núcleo. O comando canônico por classe, documentado para as próximas tasks, é:

- `rtk` estava ausente do PATH e dos locais pesquisados. Foi instalada a versão
  1.0.1 em `~/.local/bin` a partir do release oficial para usar o wrapper exigido.
- O contexto adicional de MinIO foi respeitado. Esta task não exige smoke de
  armazenamento: não iniciou MinIO, não alterou imagens do compose e não usou o
  endpoint existente. Os testes Python utilizaram suas próprias fixtures; 3
  cenários opcionais ficaram ignorados no comando padrão.

  o build .NET final apresentou 0 warnings. Kiota emite avisos de uri e
  uri-reference representados como string; essa limitação está documentada.

  Credential Manager ou notificações Windows. Nenhum comportamento dessas
  próximas fatias foi implementado nem validado nesta chamada.
- A workflow foi adicionada e seus comandos foram verificados localmente;
  não houve execução remota de GitHub Actions nesta chamada.
- Não houve branch nova, commit, merge, PR ou alteração de tasks.md, status da
  task ou flow-state.json. Foram preservadas as mudanças preexistentes em
